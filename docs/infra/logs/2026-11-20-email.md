### 3. DB の変更

新しい API はこの列と表を使うので、デプロイより先に行う。

- [x] サーバーで psql を起動して DB に接続（`ON_ERROR_STOP=1` はエラーが出たら止める指定）

```bash
cd ~/movie-log-api
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1'
```

- [x] `users` に確認日時の列を、トークン用に3つの表を追加し、既存のユーザーを全員確認済みにする（下の SQL を貼り付けて実行。`COMMIT` と出れば完了。`\q` で psql を終了）

```sql
BEGIN;

-- 確認日時。NULL なら未確認
ALTER TABLE users ADD COLUMN email_verified_at TIMESTAMPTZ DEFAULT NULL;

-- 既存のユーザーを全員確認済みにする（未確認だとログインできないため）
UPDATE users SET email_verified_at = NOW ();

-- 登録の確認用
CREATE TABLE email_verification_tokens (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    hash TEXT NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW ()
);

CREATE UNIQUE INDEX email_verification_tokens_hash_idx ON email_verification_tokens (hash);

CREATE INDEX email_verification_tokens_user_id_idx ON email_verification_tokens (user_id);

-- メールアドレスの変更用
CREATE TABLE email_change_tokens (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    new_email TEXT NOT NULL,
    language TEXT NOT NULL,
    hash TEXT NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW ()
);

CREATE UNIQUE INDEX email_change_tokens_hash_idx ON email_change_tokens (hash);

CREATE INDEX email_change_tokens_user_id_idx ON email_change_tokens (user_id);

-- パスワードの再設定用
CREATE TABLE password_reset_tokens (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    language TEXT NOT NULL,
    hash TEXT NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW ()
);

CREATE UNIQUE INDEX password_reset_tokens_hash_idx ON password_reset_tokens (hash);

CREATE INDEX password_reset_tokens_user_id_idx ON password_reset_tokens (user_id);

COMMIT;
```

- [x] 3つの表ができていること、未確認のユーザーが `0` であることを確認

```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "\dt"'
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT count(*) FROM users WHERE email_verified_at IS NULL;"'
```

### 4. `.env` の追加

- [x] サーバーの `.env` に、差出人、管理者のアドレス、ウェブの URL を追加（足りないと API が起動しない）

```text
MAIL_SUPPORT_ADDRESS=support@cinelier.app
MAIL_ADMIN_ADDRESS=<管理者のアドレス>
WEB_BASE_URL=https://www.cinelier.app
```

- `MAIL_SUPPORT_ADDRESS`: メールの差出人
- `MAIL_ADMIN_ADDRESS`: 新規ユーザーの通知とお問い合わせの宛先
- `WEB_BASE_URL`: メールに書くリンクとロゴの URL の元。`cinelier.app` は `www` 付きに転送されるので、`www` 付きにする

## 起きた問題

### 入れ替え後も v1.0.0 で起動した

`docker compose up -d` のあと、api のコンテナが `movie-log-api:v1.0.0` のまま起動していた。原因は2つあった。

- `.env` の `APP_VERSION` の書き換えが保存されていなかった。
- シェルに `APP_VERSION=v1.0.0` が残っていた。以前 `.env` をシェルに読み込んだときのもので、compose はシェルの値を `.env` より優先する。

`.env` を `APP_VERSION=v1.1.0` に直して保存し、SSH を切って入り直してから `docker compose up -d` をやり直した。
